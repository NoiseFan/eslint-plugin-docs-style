# Space Around Number

要求 CJK 文本与数字相邻时，边界处恰好保留一个空格。

## 规则详情

`space-around-number` 检查 Markdown 的文本节点。当数字直接与 CJK 字符相邻时，两者之间必须有一个普通空格；边界处已有两个或更多空格时，也会规范为一个空格。

规则识别 Unicode 数字字符。紧跟在数字后的句点（`.`）或百分号（`%`）会继续视为数字的一部分，因此 `4.0%` 会作为一个整体进行检查。

数字与拉丁文本、标点、符号或连接号相邻时，不要求添加空格。例如 `Vite8`、`2.0，` 和 `4–6` 都不属于本规则检查的 CJK-数字边界。

## 选项

此规则没有选项。

## 正确

```md
支持 123 个规则
提升 4.0% 效率
版本：2.0，现已发布。
计数从 1 开始。
第 4–6 阶段针对每个测试文件各执行一次，
_2025 年 10 月 22 日_
```

数字与拉丁文本或标点相邻时，无需额外空格也属于正确写法：

```md
Vite8Support
Since4.1.0,
Phases 4–6run once for each test file,
0.2+ 0.1 is 0.30000
```

## 错误

数字前缺少空格：

```md
支持123 个规则
```

数字后缺少空格：

```md
支持 123个规则
```

数字两侧都缺少空格（包括小数百分比）：

```md
支持123个规则
提升4.0%效率
```

CJK-数字边界包含多个空格：

```md
支持  123 个规则
支持 123  个规则
支持  123  个规则
```

## 自动修复

此规则支持自动修复。修复器会在缺失的 CJK-数字边界插入空格，并将边界处重复的空格压缩为恰好一个。它只改写受影响文本节点中的空白，不会为与拉丁文本或标点相邻的数字添加空格。

## 忽略的上下文

规则只检查 Markdown 的 `text` 节点。以下节点中的类似数字文本会保持不变：

````md
```text
支持123个规则
```

`支持123个规则`

<!-- 支持123个规则 -->
````

因此，围栏代码块、行内代码、HTML（包括注释）和 YAML frontmatter 都会被忽略。普通 Markdown 结构（如段落、标题、强调和链接）中的文本，只要解析为文本节点，就会被检查。

## 不适用场景

如果项目有意让 CJK 字符与数字直接相连、采用其他空格约定，或已经交由其他工具统一格式化，可以关闭此规则。
