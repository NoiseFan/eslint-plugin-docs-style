# Space around custom container

规范 VitePress 自定义容器起始和结束标记周围的空格，避免容器标记因缩进或空白数量不一致而产生格式差异。

## 规则详情

本规则检查 Markdown 中的 VitePress 自定义容器标记：

- 起始围栏与容器类型之间必须有且只有一个空格，例如 `::: tip`。
- 起始和结束标记不能有行首缩进。
- 结束标记只能包含围栏，不能有尾随空格。
- 起始标记的标题和属性会保留，其前导分隔空格会规范为一个。
- 围栏长度会保留；例如 `::::  info` 会修复为 `:::: info`。
- 嵌套容器会递归检查。

## 选项

此规则没有选项。

## 正确示例

符合预期的起始和结束标记：

```md
::: tip 提示
内容
:::
```

代码块中的类似文本不会被本规则检查：

````md
```md
  ::: tip
  :::
```
````

## 错误示例

起始和结束标记存在行首缩进：

```md
  ::: tip 提示
内容
  :::
```

起始围栏与类型之间缺少空格，或有多余空格：

```md
:::tip
内容
:::
```

```md
:::  tip 提示
内容
:::
```

结束标记存在尾随空格：

```md
::: tip
内容
:::␠␠
```

上例中的 `␠` 表示一个空格。

嵌套容器的每个起始和结束标记都会分别检查：

```md
::::  info
 :::  tip
内容
 :::
::::
```

## 自动修复

此规则支持自动修复。修复器只修改标记本身的空白和缩进：

- 删除起始和结束标记的行首缩进；
- 将起始围栏与类型之间的分隔规范为一个空格；
- 删除结束标记的尾随空格；
- 保留起始标记的标题、属性和围栏长度。

例如：

```md
  :::  tip 提示
内容
  :::␠␠
```

上例中的 `␠` 表示一个空格。

会修复为：

```md
::: tip 提示
内容
:::
```

容器位于文件开头或结尾时，本规则仍会修复其标记本身，但不会因为文件边界额外插入空行。容器外侧空行由 [`padding-around-custom-container`](./padding-around-custom-container.md) 负责。

## 忽略的上下文

围栏代码块中的自定义容器样式文本不会被检查或修改。除此之外，规则会检查解析到的容器标记，包括嵌套容器和位于文件开头或结尾的容器。

## 不适用场景

如果项目不使用 VitePress 自定义容器，或希望保留不同的标记空白格式，可以关闭此规则。若需要规范容器外侧的空行，请使用 [`padding-around-custom-container`](./padding-around-custom-container.md)。

## 相关规则

- [`padding-around-custom-container`](./padding-around-custom-container.md) 用于规范容器块周围的空行。
- [`valid-custom-container-type`](./valid-custom-container-type.md) 用于校验起始标记中的容器类型。
